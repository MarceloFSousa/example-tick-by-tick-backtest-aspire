# TickTest

.NET 8 / .NET Aspire solution (`TickTest.sln`) with two bounded contexts: **MarketData** (ingest ticks from a broker DLL and store them) and **Backtest** (consume stored ticks). Build with `dotnet build TickTest.sln`; a running `Web.MarketData`/`Web.TickTest` locks the DLLs and makes builds fail with file-lock errors (MSB3027) - that is not a code error.

## Repository layout

Projects live in two context folders that mirror the solution folders: `MarketData/` (`Domain.MarketData`, `Application.MarketData`, `Infrastructure.MarketData`, `Domain.DLL`, `Web.MarketData`) and `Backtest/` (`Domain.TickTest`, `Application.TickTest`, `Infrastructure.TickTest`, `Console.TickTest`, `Web.TickTest`, `Tests.TickTest`). `TickTest.AppHost` and `TickTest.ServiceDefaults` stay at the root. Commands take the folder: `dotnet run --project MarketData/Web.MarketData`, `dotnet run --project Backtest/Console.TickTest`, `dotnet test Backtest/Tests.TickTest`. `appsettings.json` of Web.MarketData is at `MarketData/Web.MarketData/`. README.md / README.pt-BR.md are the user-facing run guide (English / Portuguese): keep them in sync.

## MarketData context (implemented)

Dependency direction - everything points at `Domain.MarketData`, never at each other:

```
Domain.MarketData  <-  Application.MarketData  <-  Web.MarketData (composition root)
Domain.MarketData  <-  Infrastructure.MarketData  <-  Web.MarketData
                              |
                              +-> Domain.DLL (only Infrastructure may reference it)
```

- `Domain.MarketData` lives in `MarketData/Domain.MarketData/`. Holds models (`TradeTick`, `Asset`, `Agent`, `ETradeType`) and the ports `IMarketDataProvider` and `ITradeTickRepository` under `Business/Interfaces/`.
- `Application.MarketData`: `MarketDataService` (`IMarketDataService`) and `MarketDataWorker` (BackgroundService).
- `Infrastructure.MarketData`: `DllMarketDataProvider` + `MarketDataCallbacks` (adapter over `Domain.DLL`), `ParquetTradeTickRepository`, `CsvTradeTickRepository`, options classes.
- `Web.MarketData`: `Program.cs` wires all DI; `MarketDataController` exposes `POST /api/marketdata/historical`.

### Data flow

`MarketDataController` -> `IMarketDataService.RequestHistoricalDataAsync` (checks `ITradeTickRepository.ExistsAsync` per day, skips stored days, calls the provider **once per missing day**) -> `IMarketDataProvider.SubscribeHistoricalData` (fire-and-forget) -> DLL callbacks (`OnNewHistory`/`OnNewTrade`) -> `MarketDataCallbacks` maps to `TradeTick` -> `OnDataReceived` -> `MarketDataWorker` (only `Buyer`/`Seller` ticks, buffered in a channel, flushed every 15s and on shutdown) -> `ITradeTickRepository.InsertRangeAsync`.

### Storage

Chosen by `MarketData:Storage:Provider` (`Parquet` default, or `Csv`). One file per asset-day: `{RootPath}/{Exchange}/{Ticker}/{yyyy-MM-dd}.parquet|csv`. Inserts **append** (Parquet via `ParquetOptions.Append`, CSV via append mode) without reading existing rows. Update/Delete must read-modify-write the whole day file. `TradeTick.Id` (Guid) is generated on insert and identifies rows for update/delete. `ExistsAsync` treats an empty file as "no data".

### Configuration

`MarketData/Web.MarketData/appsettings.json` is **gitignored** (holds real broker credentials). New clones: copy `appsettings.example.json` to `appsettings.json` and fill in `MarketData:DllCredentials` (Key, User, Password, RoutingPassword, Exchange) and `MarketData:Storage`. Never commit real credentials. `MarketData:Ingestion:IgnoreNonAggression` (default `true`) makes `MarketDataWorker` drop ticks that are not `Buyer`/`Seller` before storing them.

## Domain.DLL (wrapper over the native ProfitDLL)

- P/Invoke into `C:\ProfitDLL\ProfitDLL64.dll` (`DLLBase.DLL_PATH`). **Do not rename `[DllImport]` extern methods in `DLLFunctions.cs`** - they bind by name to native exports (no `EntryPoint` set).
- Trimmed to market-data needs: `DLLService` only has `Init`, `Connect`, `GetHistory`. The trading/order methods were deliberately removed. There is **no native disconnect/logout** export, so `DllMarketDataProvider.Disconnect()` is local-only cleanup.
- Native calls return `int` (`NResult`, values like `0x80000003`). Never cast to `sbyte` - it truncates the code (`NL_INVALID_ARGS` showed up as "3").
- `ETradeType` mirrors `EAggressor` 1:1 (Buyer, Seller, RLP, Auction, Other); `tradeType.ToAggressor()` does the int mapping.
- Interop types (`TConnector*`, `NResult`, `SystemTime`) are in the global namespace; other models are in `Domain.DLL.Models`.
- Richer domain mapping is meant to happen in the application layer, not in `Domain.DLL`.

## Backtest context (Domain, Infrastructure, Application, Console and Web API implemented; first simple strategy in the core)

The Backtest context is **independent of MarketData by design**: it duplicates the models and storage code instead of referencing `Domain.MarketData`/`Infrastructure.MarketData`, and has no `Domain.DLL` dependency. Don't "de-duplicate" the two contexts.

- `Domain.TickTest`: `Models/` (`TradeTick`, `Asset`, `Agent`, `ETradeType` - copies of the MarketData ones in namespace `Domain.TickTest.Models`; plus `Order`, `Position`, `EOrderSide`, `EOrderType`, `EOrderStatus`, `BacktestRequest`, `BacktestResult`, `BacktestContext`, `ClosedPosition`, `EPositionSide`), the port `Business/Interfaces/ITradeTickRepository`, and the domain service `Business/Interfaces/IBacktestCore` + `Business/Services/BacktestCore` (`Business/Services/` is the folder for domain services), plus the static `TradeService` and `TradeRules` (see below). `BacktestCore.Run(BacktestContext, CancellationToken)` is where the engine lives: it runs **once per tick**, reads the current tick with `TradeRules.GetCurrentTick`, and **returns the updated `BacktestContext`** - callers must always keep the returned value, and so must the core with every `TradeService` call (`context = TradeService.X(context, ...)`; the context is a struct passed by value, only its lists are shared, so a discarded result loses the open `Position`). **`context.Ticks` is chronological (oldest first): the current tick is the LAST one (`Ticks[^1]`), the earlier ticks are the history** (never use `Ticks[0]`, that is the first tick of the run). The current strategy in `BacktestCore`: a tick with `Quantity > 500` is a signal in the direction of its aggressor (`Buyer` = buy, `Seller` = sell; other types are ignored); flat, it opens a position of 1; holding the opposite side, it reverses (close + open); every tick it also runs `TradeService.VerifyOpenOrders` first. `BacktestContext` holds the engine state: `Asset`, `Ticks`, the open `Position` (Quantity 0 = flat), `ClosedPositions` (`List<ClosedPosition>`) and `Orders` (lists must be initialized by the caller). `Position` has an explicit `Side` (`EPositionSide` Long/Short) and an unsigned `Quantity` (0 = flat); each reduction/close of the position appends a `ClosedPosition` for the closed quantity (Asset, Side, Quantity, EntryPrice, ExitPrice, OpenAt, CloseAt, computed `PnL`), so total realized PnL is `sum(ClosedPosition.PnL)`; `Position` has no PnL field.
  - `TradeService` (**static** domain service, no interface; pure functions over the context): `SendOrder(context, Order)`, `CancelOrder(context, orderId)`, `OpenPosition(context, side, quantity)`, `ClosePosition(context)`, `VerifyOpenOrders(context)`. Every method **returns the updated `BacktestContext`** (keep the returned value). Current price/time = newest tick (`Ticks[^1]`, throws if none). Market orders fill immediately and **net** against the single open position (add and re-average / reduce / close / flip); Limit/Stop orders are stored as `New` and can be canceled; `VerifyOpenOrders` checks every `New` order against the newest tick and fills the ones it hit (Limit buy: price <= order price, Limit sell: price >= order price, Stop buy: price >= order price, Stop sell: price <= order price), in creation order, netting each fill; a Limit fills at its own price, a Stop at the tick price. Meant to be called once per tick. Invalid operations throw (Portuguese messages). The building blocks are public static in `TradeRules` so they can be unit-tested directly: `GetCurrentTick(context)`, `IsHit(order, price)`, `Fill(context, side, quantity, price, time)` (the netting). Used by `BacktestCore`.
- `Infrastructure.TickTest`: `ParquetTradeTickRepository`, `CsvTradeTickRepository`, `TradeTickRecord`, `StorageOptions` - same code and same `{RootPath}/{Exchange}/{Ticker}/{yyyy-MM-dd}.parquet|csv` layout as MarketData, so Backtest reads the files MarketData wrote. `Order`/`Position` are not persisted.
- `Application.TickTest`: `Handlers/IBacktestHandler` + `BacktestHandler` - the entry point Console/Web call with a `BacktestRequest` (Asset, Start, End, defined in `Domain.TickTest/Models`). It reads `ITradeTickRepository` one day at a time (skips days with no data), keeps one `BacktestContext` for the whole request and, for each day, sorts the day's ticks by `Timestamp` **ascending**, then for each tick appends it to `context.Ticks` and calls `IBacktestCore.Run` once, reassigning `context = _core.Run(...)`. `Ticks` is never cleared, so the history of all days replayed so far stays in memory (a real WINFUT range can be hundreds of MB; trim it if that becomes a problem). The final `BacktestResult` is built from the returned context (realized PnL, open/closed positions, orders) plus processed/skipped days and tick count. `BacktestResult` lives in `Domain.TickTest/Models`. Registered in DI by `Console.TickTest`.
- `Console.TickTest` is the **composition root** and entrypoint of the Backtest context (`Host.CreateApplicationBuilder`): registers `StorageOptions` (from `Backtest:Storage` in `Backtest/Console.TickTest/appsettings.json`, which has no secrets and is committed), `ITradeTickRepository` (`Csv`/`Parquet` by `Backtest:Storage:Provider`, default Parquet), `IBacktestCore` -> `BacktestCore` and `IBacktestHandler` -> `BacktestHandler` (all singletons), then runs one backtest and prints the `BacktestResult`. The arg parsing/validation and result printing live in the public static `BacktestConsole` (`TryReadRequest`, `GetParameter`, `TryParseDate`, `PrintResult(request, result, TextWriter)`, `Usage`) so they can be unit-tested; `Program` only wires DI. **Parameters** come from the args (`--ticker`, `--exchange`, `--start`, `--end`) or, for any arg not given (or blank), from the `Backtest` section of `Backtest/Console.TickTest/appsettings.json` (`Ticker`, `Exchange`, `Start`, `End`); **args win**. Run with the appsettings values: `dotnet run --project Backtest/Console.TickTest`; with args: `dotnet run --project Backtest/Console.TickTest -- --ticker WINFUT --exchange F --start 2025-01-02 --end 2025-01-10` (`--start`/`--end`/`Backtest:Start`/`Backtest:End` are `yyyy-MM-dd`; a date-only `--end` means end of that day; any config key can be overridden, e.g. `--Backtest:Storage:RootPath=<folder>`). Needs the MarketData files under `Backtest:Storage:RootPath` (default `C:\MarketDataStore`, the folder MarketData writes to). Exit codes: 0 ok, 1 invalid args, 130 canceled (Ctrl+C). Not part of `TickTest.AppHost` (a console app is not an Aspire service). A run applies the core's simple strategy, so it can produce orders and PnL.
- `Web.TickTest` is the **Backtest API** and a second composition root (same wiring as the console plus the job pieces; config in `Backtest/Web.TickTest/appsettings.json`: `Backtest:Storage` and `Backtest:Reports:RootPath`, default `C:\BacktestReports`, no secrets, committed). A run can take long, so the API is **asynchronous**: `BacktestController` (`api/backtest`) `POST` takes a body (`DTOs/BacktestApiRequest`: Ticker, Exchange, Start, End; a date-only End means end of that day; blank ticker/exchange or start > end -> 400), calls `IBacktestJobService.Enqueue` and answers `202` with the `BacktestJob` (the **process id**) + `Location`; `GET api/backtest/{id}` answers `BacktestStatusResponse` (the job and, once it ended, its `BacktestReport`) or 404. JSON uses `IncludeFields = true` (the models are structs with public fields, which System.Text.Json skips by default) and enums as text.
  - `Application.TickTest/Services/BacktestJobService` (`IBacktestJobService`, singleton): jobs in an in-memory dictionary + a channel of ids. `ProcessAsync(id)` sets `Running`, calls `IBacktestHandler.HandleAsync`, builds a `BacktestReport` and saves it through `IBacktestReportRepository` (with `CancellationToken.None`, so canceled runs are reported too), ending `Completed`/`Failed`/`Canceled` with `ReportPath`. `GetAsync` falls back to the saved report when the job is not in memory (restart). `Workers/BacktestWorker` (BackgroundService) just loops `ReadQueueAsync` -> `ProcessAsync`, **one backtest at a time**.
  - Models in `Domain.TickTest/Models`: `EBacktestStatus`, `BacktestJob` (live state), `BacktestReport` (Id, Asset, Start, End, Status, timestamps, Error, `Result` = the `BacktestResult`; new statistics go here as fields). Port `IBacktestReportRepository` (`SaveAsync` returns the path, `GetAsync`, `GetPath`); `Infrastructure.TickTest/Persistence/JsonBacktestReportRepository` writes one indented file per process, `{Backtest:Reports:RootPath}/{id}.json` (`Options/ReportOptions`).
  - Limits: jobs are lost on restart unless finished; no cancel endpoint; the console does not write reports.

## Tests

`Tests.TickTest` (xUnit, net8.0, in the `Backtest` folder) tests the Backtest context: `TradeRulesTests` and `TradeServiceTests` (Domain.TickTest static services) and `BacktestConsoleTests` (Console.TickTest helpers), `BacktestCoreTests` (signals, reversals, position kept between calls, newest tick used, pending orders) and `BacktestHandlerTests` (chronological replay with the current tick last, history across days, skipped days, result built from the returned context; uses `Support/FakeTradeTickRepository`), `BacktestJobServiceTests` (job lifecycle, report saved for completed/failed/canceled, fallback to the report, worker keeps going after a failure; uses `Support/FakeBacktestHandler` and `Support/FakeBacktestReportRepository`), `BacktestControllerTests` (controller called directly over a real `BacktestJobService` with the fakes) and `JsonBacktestReportRepositoryTests` (round trip in a temp folder). Run: `dotnet test Backtest/Tests.TickTest`. **Test names follow the standard .NET `MethodUnderTest_Scenario_ExpectedBehavior` in PascalCase** (e.g. `SendOrder_NonPositiveQuantity_Throws`), not snake_case sentences. `Support/ContextBuilder` builds contexts/orders/ticks (`Empty().WithTick(price, minute, quantity, type)`, appends chronologically so the last tick is the current one; `MarketOrder`/`LimitOrder`/`StopOrder`); tests use an in-memory `IConfiguration` for the console parameters, and assert on stable text fragments only (`Position.ToString()` number formatting is culture-dependent). The static domain helpers (`TradeRules`, `TradeService`) and `BacktestConsole` are public precisely so they are tested directly; when you change their rules, change the tests with them. A running `Web.*` still locks the DLLs (MSB3027), which is not a test failure. Not covered yet: the tick storage repositories and the MarketData context.

## Conventions

- Identifiers and comments in English; **log and exception message strings stay in Portuguese** (leave them as they are).
- **Every model (struct/record/data class, including request/result types) lives in the `Models/` folder of its context's Domain project** (`Domain.MarketData` in `MarketData/Domain.MarketData/Models`, `Domain.TickTest/Models`). Never define models in `Handlers/`, `Services/`, `Persistence/` or other folders; persistence-only shapes like `TradeTickRecord` and web DTOs are the only exceptions, and stay in their own layer.
- Models are `struct`s with public fields (matches existing `Domain.DLL`/`Domain.MarketData` style). Repository/service interfaces are async with `CancellationToken` (this does not apply to the static domain services `TradeService`/`TradeRules`, which are synchronous pure functions).
- Update this file when architecture changes.
